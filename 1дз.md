Это то, на чём делают IDE.

* OpenIDE (IDE) инициирует сборку проекта, вызывает систему сборки. Может быть Gradle или Maven, соответствующие файлы должны быть в папке проекта. У меня их нет. При отсутствии Gradle или Maven проект собирается внутренними средствами IDE (без внешней системы сборки), OpenIDE сама вызывает компилятор Kotlin и собирает проект. * Запущенный системой сборки Kotlin Compiler берёт Main.kt и превращает его в байт‑код Java — файлы .class (они попадают в папку out). Это не машинный код для процессора, а промежуточный формат.

JDK — это папка на диске (например, C:\Program Files\Axiom\JDK-21). OpenIDE запускает исполняемый файл java.exe из неё, передавая ему скомпилированный код.
Gradle — если используется Wrapper, то OpenIDE запускает локальный скрипт gradlew.bat, который подтягивает нужную версию Gradle из интернета в кэш (обычно в %USERPROFILE%/.gradle).

## Ручной билд
Билд — это процесс превращения исходного кода  в то, что можно запустить: в байт‑код, JAR‑архив, исполняемый файл. Сейчас, обычно билд собирается автоматически системами сборки, но его можно сделать вручную, напрямую провзаимодействовав с компилятором Котлин.

Много времени потрачено в поисках нужных файлов. ИИ изначально говорил устаревшие названия файлов, которых у меня не было. Короче ниже инструкция под мой случай. Если вы делали те же шаги, что и я ранее, то наверное инструкция и разъяснения вам подойдут.
* Очистим файл .class из папки out
* kotlin-compiler.jar - это JAR-файл, который содержит компилятор языка Kotlin. Он написан на Java (и частично на Kotlin). То есть внутри этого JAR лежит обычный Java‑код, который умеет читать .kt, проверять синтаксис, строить абстрактное дерево и генерировать .class. У меня он лежал здесь: C:\Program Files\OpenIDE\OpenIDE Pro\plugins\Kotlin\kotlinc\lib\kotlin-compiler.jar. Сам по себе он ничего не сделает, нужен java.exe для его запуска.
* java.exe — это программа, которая умеет запускать Java‑приложения. У меня он лежал здесь: \.jdks\axiomjdk-27\bin\java.exe
* То есть надо в консоли выполнить такую логическую операцию: Приложением java.exe запустить kotlin-compiler.jar, который возьмёт Котлин-файл src/Main.kt, скомпилирует его и скомпилированный код положит в out
* Для проведения данной операции следует находиться в папке проекта для указания динамических путей к src/Main.kt и out
* Выполняем в cmd: `C:\Users\Alfa\OpenIDEProjects\Pervaya proba>"C:\Users\Alfa\.jdks\axiomjdk-27\bin\java.exe" -jar "C:\Program Files\OpenIDE\OpenIDE Pro\plugins\Kotlin\kotlinc\lib\kotlin-compiler.jar" src/Main.kt -d out`
Вышли ворнинги, но они предупредительные. Всё окей, MainKt.class оказался в out
* Теперь нужно непосредственно исполнить уже скомпилированный код с помощью java.exe: `C:\Users\Alfa\OpenIDEProjects\Pervaya proba>"C:\Users\Alfa\.jdks\axiomjdk-27\bin\java.exe" -cp out MainKt`
Вывелось
```
Hello, Kotlin!
i = 1
i = 2
i = 3
i = 4
i = 5
```
Всё окей. (-cp out (classpath) — сообщение JVM: «в этой папке лежат классы, которые можно загружать».)

## Изучить тип Decimal
Если попробовать в Kotlin (да и в большинстве языков) посчитать что-то вроде 0.1 + 0.2, то получится не 0.3, а 0.30000000000000004. Это особенность типа Double (двоичной плавающей точки IEEE 754): многие десятичные дроби в двоичной системе представляются бесконечно, и компьютер хранит их приближённо. Для игр и физики это нормально, для точных расчётов — нет. Decimal хранит число как десятичную дробь.

В Kotlin нет встроенного типа Decimal в стандартной библиотеке. Вместо этого используют:
* Java BigDecimal — «Decimal» для JVM. 
* Либо сторонние библиотеки, если нужны особые фичи.

Воспользуемся:
```
import java.math.BigDecimal
fun main() {


    val d1 = BigDecimal("0.1")        
    val d2 = BigDecimal("0.2")
    val sum = d1.add(d2)              

    println(sum)
}
```
Ответ = 0,3. Если делать через `BigDecimal(0.1)`, то будет ошибка. Нужно через строки.

У BigDecimal методы, а не операторы:
```
val a = BigDecimal("10.5")
val b = BigDecimal("3")

val plus = a.add(b)           // 13.5
val minus = a.subtract(b)     // 7.5
val mult = a.multiply(b)      // 31.5
val div = a.divide(b, 10, RoundingMode.HALF_UP)  // деление с указанием масштаба и округления
```
Деление divide обязательно требует указать масштаб (сколько знаков после запятой) и режим округления, иначе будет ArithmeticException, если результат бесконечен (например, 1 / 3). Популярные режимы округления:
* HALF_UP — 0.5 и выше — вверх.
* DOWN — всегда к 0.
* UP — всегда вверх.
* FLOOR - вниз по числовой оси, к −∞
* CEILING — вверх по числовой оси, к +∞

Лучше не использовать == для сравнения BigDecimal. Из-за масштаба числа могут быть равны по значению, но отличаться по внутреннему представлению:
```
BigDecimal("1.0") == BigDecimal("1.00")  // false, разные масштабы
BigDecimal("1.0").compareTo(BigDecimal("1.00")) == 0  // true, значения равны
```
Проверка на ноль:
```
if (value.compareTo(BigDecimal.ZERO) == 0) {
    // значение равно нулю
}
```
